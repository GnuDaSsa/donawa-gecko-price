# Project Memory

## Product and Repo Context
- Product: a Korean-first crested-gecko morph asking-price finder, not an AI image classifier.
- Core flow: choose a representative morph image → compare current lowest asking prices by platform → switch to actual-listing image cards → open the original listing.
- Preserve current listing state plus price/status history from the beginning.

## Working Preferences
- Keep the product Simple, Observable, Editable, and Replaceable.
- Mock data remains a test/development fallback only; the configured app uses live Supabase rows.
- Use precise language: “현재 최저 호가”, never “실거래가” or “확정 시세”.
- Morph and Trait are separate concepts; traits are listing badges, not automatic price groups.
- For the UI, use a clean commerce-shell visual system: warm peach outside canvas, rounded ivory app shell, white product/data cards, charcoal typography, terracotta-orange actions, and restrained sage data accents. Reference sites inform layout rhythm and hierarchy, not literal brand cloning.

## Known Pitfalls
- Never delete SOLD listings or conflate SOLD, DELETED, STALE, UNKNOWN, and collector failure.
- Never classify Lilly White + het Axanthic as Lilly Axanthic.
- Never assume a fixed number of home morph cards.
- The global codex-harness-kit wrapper is currently broken at a missing dist path; recover from repo files and record the blocker instead of retrying blindly.
- The home catalog has no fixed category count. It combines every registered morph with every `is_filterable` keyword in the database, renders only groups with current comparable inventory, and sorts them by listing count descending. New reviewed dictionary rows therefore appear without editing the home component. The 20 local WebPs under `public/morphs/` remain fallback assets only; source and rights state live in `public/morphs/ATTRIBUTION.md`. Raw seller-title tokens must never auto-create categories without dictionary review.
- Feedle collection must remain on sitemap-listed public `/pet/` HTML and JSON-LD. Never use its disallowed `/api/`, login, chat, seller, purchase, shipping, or payment surfaces.
- “Domestic everything” means exhaustively audit candidates and automate every permission-compatible public fixed-price/status surface; it never means bypassing login/app/private APIs or turning consultation-only pages into fabricated prices. The reproducible inventory and exclusions are in `docs/domestic-source-audit.md`.
- Cafe24 specialist/general shops use exact-host public category/product links and Product JSON-LD; a public category sold-out icon overrides generic Product availability. Strip title HTML and reject mixed-species/supply titles even if they also mention a crested gecko. 헬로게코 uses the same safe-field boundary through exact-host public Imweb category/Product JSON-LD pages. ZOO세요 is EUC-KR and has a stricter allowlist: public category status/thumbnail plus detail title, exact species, sex, and price only; never seller body/name/address/contact.
- Unsupported/ambiguous morph labels are logged and omitted rather than force-classified.
- A price/image toggle is a layout toggle only. Both sides must render the same one-lowest-listing-per-platform comparison set and the same empty-platform rows; never feed the image side the full listing collection.
- Danawa is a structural benchmark, not a skin to clone: retain prominent minimum, dense facts, section tabs, explicit conditions, price order, and original-source actions while keeping the 도나와 parody identity and animal-specific semantics.
- Price distribution and shop comparison have different populations. The boxplot uses all ACTIVE + FIXED + numeric listings on active platforms; the shop table and both view modes use exactly one lowest listing per platform.
- The full-listing catalog is a third, explicitly separate view: it uses the same population as the boxplot, remains price-sorted, filters by platform, and shows 12 more records per click. Never substitute it for the platform-minimum comparison.
- Boxplot quartiles use R-7 interpolation and Tukey 1.5×IQR observed whiskers. Always show exact full min/max and separately label outliers so a compressed box cannot hide the amount pool.
- Home market cards must be data-backed rather than decorative: each card shows the current comparable listing count, active source count, and minimum asking price. Header search must match Korean name, English name, and registered aliases.
- Home category-card imagery follows the displayed minimum: select an ACTIVE + FIXED listing at the absolute minimum price and show that listing's public image. When several listings share the minimum, prefer an imaged listing within that exact-price tie; never jump to a more expensive listing just to obtain a photo. Only when the selected minimum has no usable image, or its image fails in the browser, may the home category card use its curated representative image. This fallback applies only to home discovery cards; individual listing cards still show `이미지 없음` and never borrow a representative.
- Listing images must preserve provenance: render only the current listing's `imageUrl`. When it is absent, blank, or fails to load, show a neutral `이미지 없음` placeholder; never substitute a morph representative or generic gecko photo because repeated fallback images falsely imply those animals belong to the listings.
- Shop geography must preserve provenance too: accept only official public business/store pages, never a private seller address or inferred home location. Keep uncertain geocodes null. The nearby UI must have no fixed substitute location: user GPS is explicit-action, client-memory-only input and must never reach Supabase, logs, analytics, or browser storage. Permission denial leaves the nationwide view unchanged. After a successful GPS read, center exactly on that coordinate at Kakao level 4; the nationwide reset effect must not override the location focus.
- Fulfillment claims are scoped evidence, not a shop-wide guess. Distinguish live animals from all products/supplies and available from unavailable/confirm-required. Generic parcel text does not prove reptile parcel delivery. Platform inventory is not branch stock unless a source proves it.
- `내 주변 매장` is a primary utility, not a header-only icon: retain a visible text entry in the mobile header, a home band directly below search, and the fixed-reference/region actions in the first viewport of `/nearby`.
- Home has one morph-discovery surface: the availability-filtered image catalog. Do not reintroduce a separate top-four/current-signal morph ranking below it; it duplicates the same prices and lengthens the page without enabling a different task.
- Circular platform marks use their own `inline-grid` centering rule and must be excluded from selectors that lay out the adjacent platform-name text. Verify optical centering in the rendered browser, not from CSS intent alone.
- Price-distribution boxplots are vertical: minimum at the bottom, maximum at the top, quartile box and median on the same axis, outliers mapped upward with slight horizontal jitter, and exact statistics listed below. Preserve a 7.5% minimum visual IQR height so a narrow quartile band remains legible without changing the stated values.
- Korean product copy should prefer short noun phrases and direct labels over repeated polite explanatory endings such as `~입니다` or `~해요`. Keep necessary price-provenance, fulfillment, GPS, and source-safety disclaimers, but compress them rather than removing them.
- Prefer action-and-data-only UI. Do not add trust strips, explanatory footers, decorative English eyebrows/status slogans, or guide sections that restate controls and numbers already visible on the page. Keep only task-enabling labels, values, state/error text, required map attribution, and the shortest safety boundary beside the relevant data.
- Nearby-store coverage is independent from price coverage. A store-owned official location page may support a location-only directory row even when no numeric catalog exists, but it must create zero price/listing rows and keep visit policy at `CONFIRM_REQUIRED`. `/nearby` should look like a familiar Korean map app: compact search/filter controls, synchronized result list and map, visible `가격 미연동` state, nationwide South Korea default, explicit GPS distance sorting, Kakao deep links, and map pan/zoom constrained to South Korea. Kakao Places search results are discovery-only UI rows and must remain visibly separate from officially verified stores and the price database.
- Nearby markers must not encode source provenance through different colors, letters, numbers, or shapes. Use one common store pin in the list and map; communicate `매장` versus `지도검색` only through the existing text badges and selected-card facts.
- The nearby search box has two related behaviors: typing filters known store names/regions/addresses, while Enter or the map-pin submit button resolves a general Kakao place name or exact address and then restores the full directory sorted from that reference point. Use Places keyword search first and address geocoding as fallback. Keep the searched coordinate in client memory only, show a short not-found state, and never pretend a zero store-text match means the place itself does not exist.
- The `다나와 → 도나와` landing action plays on a direct home load and replays after every full refresh of the home page. Client-side logo navigation or browser back to home must not replay it. Keep this boundary in current-document memory rather than session/local storage; the skip button only ends the current playback.
- Every non-home route derives a visible header back button from `usePathname()` and calls browser history. Do not require each page to opt in manually, keep the `뒤로` label visible at every viewport width, and render the shared header on the custom 404 page too. Keep the brand mark as a separate home link; returning through either control must not retrigger the landing action within the same document.
